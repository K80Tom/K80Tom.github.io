多模态素材解析入库

负责图片、视频、音频及 Excel 素材解析。对非标准 Excel 图文混合资产，结合模板规则与模型识别，将多视图图片、参考图和描述绑定到对应实体；PostgreSQL 保存结构化资产与来源，TOS 保存媒体，向量索引异步同步。

RAG 检索增强与混合召回

为导演工作台与 Agent 素材问答提供共用检索能力。围绕角色、场景、道具和短文本查询，组合向量语义召回与定制词法召回，引入 jieba、领域词典、多字段加权及元数据过滤，迭代融合排序和规则重排。

Agent 工具与会话链路

参与 Pi Agent 助手研发，将素材检索、项目资产关联、生成卡准备、任务查询和导演台指令封装为 5 个受控业务工具。通过输入输出约束、操作权限、会话管理、SSE 事件及审计记录，连接“找素材 → 选参考 → 准备生成”。

Grill 信息充分性检查

设计并实现生成准备前的检查流程：规则预检 → 模型语义评估 → 候选补全或反问。先用程序确认素材、参数和创作要求是否齐全，必要时再调用模型判断语义，引导用户补齐缺失信息。

两阶段剧本拆解

参与“Agent 多工具拆解 → 固定 Skill 结构化拆镜”流水线。先用 7 类业务工具提取梗概、场次及角色、场景、道具、服装、音频候选，再生成分镜细节、时长和视频提示词；以原文引用、结构校验与草稿确认控制正式写入。

02 / FROM ASSETS TO GENERATION

从素材入库，到可确认的生成准备。

  1. 01

    整理素材与来源

    接收图片、视频、音频与 Excel，解析媒体和文本的对应关系，将参考图、多视图及描述绑定到资产实体。

  2. 02

    入库并建立检索索引

    结构化资产与来源写入 PostgreSQL，媒体保存至 TOS；异步同步向量索引，供工作台和 Agent 共用。

  3. 03

    混合召回与选取参考

    查询同时进入语义召回与领域词法召回，结合元数据过滤、融合排序和规则重排，返回可关联到项目的参考资产。

  4. 04

    检查生成准备是否充分

    Grill 先做规则检查，再按需进行语义判断。缺少素材、参数或创作信息时，提供候选或继续反问。

  5. 05

    拆解剧本并确认草稿

    Agent 提取场次和资产候选，固定 Skill 生成结构化分镜；绑定剧本版本、提示词版本和原文引用，由用户确认草稿。

  6. 06

    准备生成卡与提交任务

    受控工具准备生成卡，实际付费提交经过业务后端确认与额度校验；任务查询与 SSE 事件返回执行状态。

调用额度落在运行时

单次请求最多调用 4 次工具、最多准备 1 张生成卡，设置 90 秒超时。生成卡准备与付费任务提交分离，实际生成由业务后端确认并校验额度。

正式数据来自确认过的草稿

拆解结果绑定剧本版本、提示词版本与候选来源。规则变化后拒绝旧版本继续执行；草稿和正式数据分离，以确认事务与幂等处理避免重复写入和过期结果落库。

04 / INDEPENDENT PROJECT · EARLY PREVIEW

OHAO，把整集制作接成可恢复的流程。

OHAO 是同领域的独立公开项目，定位为面向中文短剧的本地 AI 制片工作台。它将剧本拆解、资产、分镜、镜头生成、技术复核和合片组织为一次持久化生产运行；当前入口是仓库中的 shortdrama-agent-lab/。

这是独立产品展示。它不依赖中文在线旧平台的 API、数据库、账号或部署环境；上方企业项目的职责、日期与检索指标不移作 OHAO 的成果。

十阶段执行流程
  1. 01

    输入与生产预检

    冻结项目、剧本版本、画幅、目标时长、生产策略与本次运行的预算授权。

  2. 02

    剧本拆解

    提取人物、地点、道具和对白事实，经过确定性检查，由用户或 Agent 采用候选版本。

  3. 03

    资产匹配与补齐

    按名称和别名匹配资产；歧义停下确认，真正缺失的资产才进入生成与入库流程。

  4. 04

    分镜设计

    生成并检查镜号、引用、对白覆盖及顺序，采用后展开每个镜头的生产任务。

  5. 05

    3D 导演预演

    按规则为需要的镜头建立白模，将机位、焦距、运镜和站位转为文字构图约束。

  6. 06

    多候选视频生成

    绑定有序参考图片与构图约束，生成多个带供应商原生音轨的镜头候选，再安全下载到本地。

  7. 07

    候选抽卡与选优

    仅接收已入库的本地 MP4，用画幅、分辨率和音轨等指标形成技术推荐，或等待人工选择。

  8. 08

    镜头技术复核

    检查文件、哈希、画幅、时长与音轨；失败时在限次内重新生成受影响镜头，并带入失败项。

  9. 09

    时间线合成

    按采用后的分镜顺序读取已选本地视频，由 FFmpeg 合成整集 MP4，保留不可变时间线清单。

  10. 10

    成片校验与交付

    重新核验本地成片和冻结的目标时长。校验通过才形成可下载交付，失败则停在具体问题上。

可以停下来，也能从原位置继续。

三种运行模式

全自动采用通过检查的文本候选和技术推荐视频；关键节点确认在核心阶段停下；共同导演逐阶段确认。预算不足、输入歧义或外部任务未知时，所有模式都保留阻断。

持久化与局部返修

运行与任务写入 PostgreSQL，服务重启后按状态恢复。返修只使受影响的下游结果失效，保留既有记录；未知付费任务查询原任务，避免再次提交。

运行预算与媒体证据

调用前预留预算，额度不足暂停；当前以配置估算控制运行预算，不等同于供应商最终账单。视频安全下载到本地，校验哈希与媒体信息后才进入合片。

当前实现范围与下一步

已实现：本地整集生产总控

公开代码已包含十阶段 DAG、任务与预算状态、文本拆解、资产匹配、分镜、多候选视频适配、技术复核、有限返修、合片和交付。真实生成需要本机模型连接与每次运行的明确预算授权。

技术复核的范围

当前检查容器、哈希、画幅、时长与音轨，读取分辨率参与评分；尚不能自动确认人物、动作、剧情、表演与镜头连续性，成片仍需人工观看。

3D 与声音的范围

自动白模由明确规则生成，以 prompt-only 文字约束参与视频生成，尚未传入 3D 渲染图或原生相机参数。声音使用视频供应商音轨，未包含独立配音、口型、配乐、混音及字幕子流程。

Early Preview

当前为本地单机产品，未提供公开在线演示站；分布式调度、对象存储/CDN、多用户权限与供应商最终账单回填尚未实现。离线测试或界面导览不等于真实模型全链路质量验收。
