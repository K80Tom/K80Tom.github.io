记忆系统

我负责的核心模块：会话记忆 + 长期记忆 + 分层压缩

ConversationProjection 会话快照结构

ConversationProjection（Redis，TTL 30 天） ├── Rollups 很早以前对话的分层摘要 ├── Episodes 已压缩的对话片段 ├── RawMessages 最近未压缩原文 ├── AgentStatus 当前 Agent 工作状态 ├── LastSequence 已处理到的消息序号 ├── ProjectionVersion / Revision ├── Dirty / DirtyReason └── UpdatedAt

分层压缩流程

RawMessages最近原文
超出预算 →
Episode分块摘要
达到 fanout →
Rollup L1折叠汇总
继续达到 fanout →
Rollup L2/L3更高层汇总

压缩在候选快照中完成，生成、验证全部成功后才通过 CAS 版本校验替换 Redis 当前快照，确保并发安全。软阈值触发后台压缩，硬阈值触发请求前压缩。

我的职责

用户记忆系统 · 会话上下文管理 · iOS 原生交互 · 反馈业务后端

结构化用户记忆

参与用户长期记忆模块开发，基于 MySQL 管理用户偏好、个人资料、习惯与目标等结构化事实；支持记忆更新、撤回及分类禁记策略，在对话前加载有效记忆，为个性化回复提供依据。

记忆提取与按需注入

在会话回复后异步调用 LLM 提取稳定、用户明确表达的事实，结合置信度与禁记策略过滤候选；采用「记忆目录 → 相关引用选择 → 完整事实加载」的方式组织长期记忆，控制无关内容进入模型上下文。

会话上下文管理

结合 Redis 会话快照管理近期原文、分段摘要及当前交互状态；按 Token 预算组织历史上下文，通过 Episode 分段摘要与 Rollup 汇总保留旧对话中的关键事项、用户边界和未完成承诺。

iOS 原生交互

基于 SwiftUI 与 MVVM 实现反馈信箱交互原型，覆盖信封列表、拆信阅读、反馈编辑与本地图片预览；通过独立 ViewModel 管理页面状态、草稿和异步图片任务，实现缩略图降采样及任务取消处理。

反馈业务后端

基于 Go、GORM 设计会话、消息、附件三类数据模型，实现反馈创建、消息追加、历史查询与官方回复等能力；接入公司媒体服务保存图片，数据库维护文件标识及附件元数据。使用事务保证原子写入，结合复合唯一键与请求指纹识别重复提交及内容冲突。

接口与工程交付

编写 Thrift 接口契约及 RPC 实现，完成 Go SDK 更新、测试泳道部署与创建反馈接口的网关配置发布；补充请求重放、权限隔离、分页及字段映射等自动化测试。
